# SOLIVY Finance v2.6.0 — Dual Mode

## What this build provides

### Offline client
The root application remains the existing local Windows application:

Browser → localhost:3000 → Next.js API → better-sqlite3 → persistent LIVE/TEST SQLite files.

### Online / Vercel-ready
`VERCEL-FRONTEND/` is a frontend-only Next.js application:

Browser → Vercel → `/api/*` rewrite → SOLIVY API server → persistent database.

The API source and database remain on the server. The Vercel package intentionally contains no `app/api` or `better-sqlite3` code.

## Why this architecture

The current application uses synchronous `better-sqlite3` and persistent local SQLite files. Vercel's normal serverless filesystem is not a suitable place for those database files. This build therefore avoids changing the accounting/database logic merely to force SQLite onto Vercel.

If you later want an all-Vercel deployment, the API/database layer should be migrated separately to a managed PostgreSQL provider and async database access.

## Existing business logic

No accounting logic is intentionally changed by the dual-mode packaging. The existing v2.5.11 application is preserved as the offline/server backend.

## Online deployment

1. Put the root application on a persistent server and run it with `npm run build && npm start`, or use the included Docker setup.
2. Give it an HTTPS URL such as `https://api.finance.example.com`.
3. Deploy `VERCEL-FRONTEND/` as the Vercel project.
4. Set `SOLIVY_BACKEND_URL` and the same `SESSION_SECRET` in Vercel.
5. Test login, company switching, LIVE/TEST, payments, purchases, vendor outstanding, withdrawals and transfers.
